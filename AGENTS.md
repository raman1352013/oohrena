Read this file completely before changing anything. Then read:
- `docs/OOHRENA_MVP_Compulsory_Modules_v1.0 (1).pdf` — **the only requirements source**. Every feature, rule and acceptance test comes from it.
- `docs/REMAINING_WORK.md` — what is still to be built, in order, with acceptance criteria.

Ignore any other document in `docs/` (for example an older vendor's handover PDF). It is not a requirement, and it is deliberately kept out of git.

## 1. What this is

OOHRENA is a 360° outdoor + digital advertising marketplace. Clients find media and request quotes; Central Admin reviews every inquiry and quote; vendors list verified inventory, execute work orders and upload proof; Finance verifies money with maker-checker. **Core principle: Client Transparency First** — every inquiry, quote, booking, work order, proof and payment has a traceable record and an audit trail.

## 2. Repository layout (npm workspaces monorepo)

```
apps/api          Express 5 + MongoDB (Mongoose 9) REST API, all routes under /api/v1
  src/config.ts     every environment variable, validated with zod
  src/app.ts        mounts all routers (order matters — see §6)
  src/models/       Mongoose schemas (one file per domain)
  src/services/     business logic (quotes, availability, execution, finance, inventory, search, session)
  src/routes/       HTTP layer: validation + permission + call service + shape response
  src/lib/          audit, ids, crypto, storage, signed URLs, pdf, csv, transactions, errors
  src/middleware/   auth/session/RBAC/CSRF, validation, uploads, error handler
  scripts/          seed (test accounts), dev-memory (in-memory DB), create-staff (first admin), mongo-app-role.js
  test/             vitest + supertest + mongodb-memory-server; fixtures.ts builds the full chain
apps/web          React (TanStack Start/Router) frontend, renders client-side
  src/routes/       file-based routes (src/routeTree.gen.ts is GENERATED by the build — never edit)
  src/lib/*-api.ts  TanStack Query hooks per domain (api.ts is the only fetch wrapper)
  src/lib/auth.ts   session hooks + route→role map used by AuthGate (UX only; the API enforces access)

                  status lists/transitions, quote/finance/availability maths. Change rules here, once.
docs/             requirements PDF + these instruction documents
```

## 3. Commands (run from the repo root, Node 22+)

```sh
npm install                 # .npmrc sets legacy-peer-deps (needed for a vitest peer-dep bug in npm 10)
npm run dev:api:memory      # API on :4000 with an in-memory MongoDB + seeded test accounts (data resets on restart)
npm run dev:api             # API against MONGODB_URI from apps/api/.env (must be a replica set)
npm run dev:web             # web on :8080, proxies /api to :4000
npm test                    # all workspaces (api tests start their own in-memory replica set)
npm run typecheck           # all workspaces
npm run build -w @oohrena/web
```

`apps/api/.env` is git-ignored. Copy `apps/api/.env.example`. Test accounts are listed in README; their password is `SEED_PASSWORD` in `apps/api/.env`.

## 4. Non-negotiable rules (from the MVP document — never weaken these)

1. **Every endpoint is authorised on the server**: role check via `requirePermission("<permission>")` from the matrix in `packages/shared/src/roles.ts`, **plus an object-level check** (own / assigned / all). A record that exists but isn't the caller's returns **404**, not 403, so IDs can't be probed. Hiding a button is never security.
2. **Validate every input with the shared zod schema** (`validateBody(schema)` / `parseQuery(schema, req)`). Use `.strict()` where unknown fields must be rejected.
3. **Money is computed on the server only** (`computeQuoteTotals`, `payableFor`, `cancellationFor` in `packages/shared`). Never trust amounts sent by a client. Screens may only *preview* with the same shared functions.
4. **Every critical action calls `audit(req, { action, entity, entityId, before, after, reason })`** — status changes, approvals, overrides, money, exports, views of sensitive data (KYC docs, bank details, payment proof). The audit log is append-only; never add update/delete paths for it.
5. **IDs come from `nextId("<PREFIX>")`** (`apps/api/src/lib/ids.ts`, formats in `packages/shared/src/ids.ts`): `USR-000001`, `VND-…`, `LD-2026-000001`, `QT-2026-000001-V1`, `BK-…`, `WO-…`, `CMP-…`, `PAY-…`, `TXI-…`, `ISS-…`, `PRF-…`, `INV-<CAT>-000001`. Never reuse or edit an ID.
6. **Status changes follow the transition tables** in `packages/shared` (`LEAD_TRANSITIONS`, `LISTING_TRANSITIONS`, `KYC_TRANSITIONS`, `BOOKING_TRANSITIONS`, `WO_FLOW`, quote/payment rules). Invalid jumps return `409 INVALID_TRANSITION`.
7. **Reasons are mandatory** for reject / suspend / override / cancel / proof rejection / payment rejection.
8. **DEMO inventory is never bookable or quotable**, and never shown as verified. Unconfirmed availability is labelled "Subject to vendor confirmation". GPS is labelled exactly as captured — never "GPS verified".
9. **Maker-checker for money**: whoever records a payment can never verify it; only Finance verifies. Payments need a proof file and start `unverified`. No hard deletes of financial records; edits only before verification, with `PaymentHistory` rows.
10. **Sensitive data**: bank account numbers and KYC/payment files are AES-256-GCM encrypted at rest (`lib/crypto.ts`, `saveUpload(..., encryptAtRest: true)`); show bank numbers masked except to Finance (logged). Proof media is served only through short-lived signed URLs (`lib/signed-url.ts`). Uploads are type-checked by file signature (`sniffMime`), not by extension.
11. **No secrets in the repo** — not in code, tests, docs or commit messages. Real credentials live in the hosting provider's secret store.
12. **Double booking is prevented in the database layer**: every hold/booking runs in a MongoDB transaction that bumps `Inventory.availabilityRev` (see `services/availability.ts`). Keep that pattern for anything that consumes capacity.
13. **Phase 2 features are out of scope** (AI recommendations, dynamic pricing, payment-gateway escrow/splitting, native apps, social ads). Don't build them.

## 5. How to add a feature (follow the existing pattern)

1. **Contract** in `packages/shared/src/<domain>.ts`: zod input schema, status enums/transitions, pure maths. Export it from `src/index.ts`. Add a permission to `roles.ts` if needed. Add a unit test next to it if there is logic.
2. **Model** in `apps/api/src/models/`. Business IDs are the `_id`. Add indexes for every query you add.
3. **Service** in `apps/api/src/services/` for anything beyond simple CRUD. Use `withTransaction` when several documents must change together.
4. **Route** in `apps/api/src/routes/`: `requirePermission` → validate → service → shaped response `{ data }`. Errors: throw `badRequest / notFound / forbidden / AppError(409, ...)` — the error handler produces `{ error: { code, message, details } }`. Mount it in `src/app.ts`.
5. **Tests** in `apps/api/test/`: use `fixtures.ts` (`approvedVendor`, `liveListing`, `bookedWorkOrder`) and `helpers.ts` (`createStaff`, `registerClient`, `bearer`). Write the MVP document's "how to test" rows as tests, including the negative cases (wrong role → 403, other user's ID → 404, missing reason → 400, invalid transition → 409).
6. **Web**: hooks in `apps/web/src/lib/<domain>-api.ts` (TanStack Query; invalidate the right keys), UI in `src/components/app/...` using `kit.tsx` (`KCard`, `Btn`, `Pill`, `Empty`, `Row`) and `AuthShell.tsx` (`Field`, `FormError`). Every screen needs loading, empty and error states. Add any new route prefix to `ROUTE_ROLES` in `src/lib/auth.ts`.
7. **Verify**: `npm test`, `npm run typecheck`, `npm run build -w @oohrena/web`, then click through the flow in a browser with the seeded accounts.
8. **Update** the module status table in `README.md` and tick items in `docs/REMAINING_WORK.md`.

## 5a. UI copy and layout (keep it as simple as Linear / Apple Notes)

- **A heading names the screen.** No eyebrows, taglines or explanation paragraphs under it.
- **Empty states name what is empty** (`<Empty title="No bookings" />`). `Empty` has no hint prop on purpose.
- **Labels are short nouns** ("City", "Budget (₹)"). No `placeholder="e.g. …"` examples; `Field` has no hint prop.
  Rules a user must know go in the label (`"Your rate (₹, private)"`) or come back as a validation error.
- **Keep text that is state or a rule with consequences** (status pills, "Subject to vendor confirmation",
  "Changing location, rate or size sends it back to review"). Cut text that explains how the product works.
- If a screen only makes sense with helper text, change the layout instead of adding words.
- Kit (`components/app/kit.tsx`) is the only set of primitives: `KCard`, `Pill`, `Btn`, `Empty`, `Row`, `PinLogo`.

## 6. Known pitfalls (learned the hard way — read before debugging)

- **Router shadowing**: `routes/vendors.ts` ends with a catch-all that returns 404 for unknown `/vendors/me/*` paths. Any new `/vendors/me/...` endpoint must be added **inside `vendors.ts`** (see `/me/payables`, `/me/proofs/overdue`), not in another router.
- **Mongoose 9 strict typing**: filters/updates with a plain `string` where the schema has an enum fail typecheck. Type the variable as the enum, or cast `as never` at the call (pattern used throughout). Use `returnDocument: "after"` (not `new: true`). Update pipelines (arrays) are rejected unless `updatePipeline` is set — avoid them.
- **Transactions need a replica set.** MongoDB Atlas is one; a plain local `mongod` is not. Tests use `MongoMemoryReplSet`.
- **mongodb-memory-server** downloads a ~370 MB binary once into `node_modules/.cache/mongodb-memory-server` (pinned in `apps/api/vitest.config.ts`). If a download is interrupted, delete `~/.cache/mongodb-binaries/*.lock` and `*.downloading`.
- **Web TypeScript uses `exactOptionalPropertyTypes`**: optional props must be typed `x?: T | undefined` when you pass `undefined`.
- **`src/routeTree.gen.ts` is regenerated** by `npm run build -w @oohrena/web` (or `dev`). New route files show type errors until you build once.
- **Dates** are plain calendar days `YYYY-MM-DD` stored as UTC midnight; "today" is `todayIST()`. Ranges are inclusive.
- **Cookies + CSRF**: the browser uses the HttpOnly `oohrena_sid` cookie; state-changing requests must come from an origin listed in `CORS_ORIGINS`. Scripts/tests use `Authorization: Bearer` (send `X-Auth-Mode: token` on login).
- Remaining demo code: `apps/web/src/lib/store.ts` (localStorage demo store) is still used only by `reports.tsx`, `partner.tsx`, the two `print.*` routes, `RequestQuoteDialog.tsx` and the admin export in `AppHeader.tsx`. Replace those with API data and then delete the store (tasks in REMAINING_WORK.md).
- `apps/web/AGENTS.md` contains a Lovable block. The web app was moved out of the Lovable repo root into the monorepo, so Lovable sync no longer applies; keep the project rules in that file current or merge them here.

## 7. Definition of done for every change

- All tests pass (`npm test`), typecheck clean, web builds.
- New behaviour has API tests including negative/permission cases.
- Critical actions are audited; inputs validated; permissions + ownership enforced.
- UI has loading / empty / error states, works at phone width, and uses the existing design kit.
- README status table and `docs/REMAINING_WORK.md` updated.
- Commit with a clear message on a feature branch; never commit `.env`, uploads or credentials.
